# UI TrueMoon Tales Studio

## Выбор контура

- Начни с [правил Studio](../../../AGENTS.md), [плана](../../../Plan.md) и
  [руководства по оформлению окна](../../../src/WindowDesign.md). Основной
  настольный UI schema 2 находится в
  [Presentation](../../../src/TrueMoon.Tales.Studio/Presentation/).
  Для задач Python/Web schema 1 используй [static](../../../static/) и
  [контракт HTTP](../../../API.md).
- Перед правкой настольного View сверь [версии пакетов](../../../src/Directory.Packages.props).
  В общей рабочей области используй
  [truemoon-ui](../../../../TrueMoon/.agents/skills/truemoon-ui/SKILL.md) для
  Fluent-композиции, стилей и владения. Новые Fluent-методы применяй, когда они
  доступны в выбранной версии Studio.

## Рабочий интерфейс

1. Сохраняй основную площадь для превью и таймлайна. Действие, выбор и режим
   просмотра должны читаться из панели и подписей. Для Dark/Light используй
   существующие тему и роли. Начни с `SceneView`, `SceneViewStyle` и
   `SceneViewFactory` в каталоге `Presentation/Scene`, если работа касается
   редактора. Сохраняй фокус, курсор и выбор при перестройке отдельных панелей.
2. Различай выбранный дубль для просмотра и назначенный материал клипа.
   Перед изменением сценария, библиотек или монтажа сверяй
   [модель проекта](../../../ProjectModel.md). Сохраняй идентификаторы и связи.
   Проверяй курсор, диапазон и длительность в кадрах рабочего проекта.
3. Drag и правки инспектора могут менять локальный черновик. Команду записи
   отправляй при подтверждении с захваченной `expected_revision`. При конфликте
   сохраняй черновик. Поздний ответ применяй, только если проект, элемент и
   операция всё ещё актуальны. Сценарий чтения или просмотра оставляет запись
   за явной командой, как и обновление формата проекта.
4. Подготовка задания, запуск и сбор результата имеют отдельные команды.
   При смене режима сохраняй доступ к состоянию фоновой операции и учитывай
   владельца backend, медиапотока и тестовых процессов.

## Проверка

- Начни с [UITesting](../../../src/UITesting.md). Для настольного UI используй
  настоящий View из фабрики и маршрутизируемый ввод `UiSession`. Для редактирования
  проверь состояние интерфейса и проекта на изолированной копии, включая Escape,
  успешное подтверждение и конфликт ревизии, когда они затронуты.
- Для визуального изменения используй CPU raster Skia с фиксированными шрифтами.
  Проверяй читаемость кириллицы, геометрию панелей, resize и scale, относящиеся к
  задаче. Для физического ввода, DPI и поведения реального окна используй
  [управляемую QA-сессию](../../../src/QASessions.md) и заверши свои процессы.
- Для Python/Web выбирай соответствующие тесты интерфейса и API. Для изменений
  превью или монтажа проверяй также результат воспроизведения либо CPU-экспорта,
  если изменение затрагивает тайминги, звук, переходы или титры.
