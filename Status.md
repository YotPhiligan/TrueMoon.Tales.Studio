<a id="studio-csharp-workflow-run"></a>
## Исполнение workflow «Генерации по черновику» на C#, 21.11.2026

Studio **1.2611.21.19-alpha** запускает отдельную роль того же EXE после
записи `Run/Launch.json` с SHA снимков и воркера. Воркер через Python
вызывает CPU-валидацию и сервер ComfyUI. C# сверяет владельца временного
порта, фиксирует попытку перед POST, опрашивает историю с дедлайном и
следит за прогрессом. Отмена и авария backend завершают принадлежащие
заданию процессы. Потерянный ответ не запускает повторный POST.

Сборщик проверяет 24 кадра/с, число и размер кадров, отсутствие звукового
потока в MP4, размер последнего PNG и диагностику SageAttention/H3. Квитанция
завершения связывает SHA результата и сборки. Backend публикует MP4 в
`video/` и регистрирует дубль под единственным writer. При повторном
открытии он восстанавливает завершённую публикацию по квитанции. Для
прерванного запуска без результата остаётся запись о попытке.

Сквозной сценарий UiSession/Enerit использует настоящий backend и воркер,
а GPU-ответы возвращает изолированный имитатор ComfyUI. Фикстуры считают
POST для каждого задания и проверяют остановку, аварию backend и потерю
ответа после приёма запроса. Проверены восстановление между сбором и
публикацией, отказ при звуке и выходе из каталога, проверка SHA MP4 и
повторный сбор без новой записи в истории проекта. Старые Python-скрипты
сохранены для совместимости SHA подготовленных заданий и отдельного
ручного контура. Контактный лист и телеметрия NVIDIA относятся к ручному
диагностическому прогону. GPU-приёмка остаётся в UI-02.

Локально опубликованный EXE прошёл 4 целевых теста. При первом полном
прогоне два теста CPU-экспорта упали. Оба прошли при отдельном повторе,
затем полный Release-прогон дал 904 пройденных, 5 пропущенных и 0 ошибок.

Отдельный C#-сервис через Enerit следует за этапом HTTP. [Порядок перехода](Plan.md#прототипы-и-порядок-перехода).
