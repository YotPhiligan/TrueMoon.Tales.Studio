# Сценарий и фиксированное окно — Studio 0.5

31.10.2026. Первый этап UI-06A и начальная карточка сегмента. Перезапустить [Start-Studio.cmd](Start-Studio.cmd) после обновления и обновить страницу.

## Работа со сценарием

Studio открывает сценарную навигацию. Если уже есть монтаж, показаны его сегменты и использования блоков с прежними ID, временами и паузами. Чтение не переписывает проект. Исследовательские карточки и прочие исходники доступны через «Библиотека исходников»; они автоматически в сценарий не попадают.

1. Нажать «Добавить сегмент» / «+ Сегмент» в сценарии. Заполнить название, описание и известные времена. Начало + окно дают конец; изменение конца пересчитывает длину. Неизвестные поля можно оставить пустыми.
2. В карточке сегмента нажать «+ Пустой блок» и задать название, описание действия и плановую длительность. Блок сразу становится текстовой заглушкой на шкале. «+ После» вставляет между существующими блоками.
3. «Описание и время» меняет постановку, длину и явную паузу перед блоком. Стрелки меняют порядок. Следующие блоки сдвигаются последовательно внутри фиксированного окна; соседние сегменты и музыка сохраняют свои позиции.
4. «+ Из библиотеки» создаёт новое сценарное использование существующего источника. Название/описание этого использования независимы от других. В его форме можно выбрать готовый дубль и вход в видео. Само назначение дубля не меняет скорость или отбор; явная монтажная правка участка/скорости доступна в [Studio 0.8](ClipEditing.md).
5. «Материалы и промпт» открывает существующий редактор исходного блока. Вернуться к сегменту можно через боковую панель. Новый пустой блок получает отдельную черновую карточку в библиотечной группе «Сценарные заготовки»; его описательный текст не записывается в H3-промпт.

Вверху видны начало/конец, окно и свободное время. При сумме блоков 7 с в окне 8 с останется секунда. При сумме 9 с появится конфликт «Не хватает 1 с». Такой план сохраняется как намерение: кадры не обрезаются, скорость не меняется, окно автоматически не растёт. На таймлайне видны плановые позиции, а последний допустимый монтаж остаётся сохранённым. Общий просмотр блокируется до исправления неопределённого времени/конфликта. Отдельные исходные дубли доступны в редакторе.

Время неизвестного блока не подменяется нулём: его позиция и позиции следующих блоков остаются неопределёнными. Не размещённое окно видно в сценарии; точного диапазона на горизонтальной шкале у него ещё нет.

Кнопки «В списке» меняют только порядок сегментов в сценарном списке, сохраняя их временные окна. Для реального переноса окна изменить начало сегмента или перетащить его на таймлайне. Пересечения/переполнения показываются как конфликты. Перенос блока в другой сегмент перетаскиванием пока не поддержан: добавьте использование источника в нужной карточке и перенесите описание вручную, сохраняя прежнее до проверки.

## Таймлайн, сохранение и отмена

Описания и порядок сценарных использований хранятся в timeline.scenario внутри Production/Studio.project.json. Общие ID связывают карточки и шкалу. Допустимый сценарий обновляет монтажные сегменты/клипы атомарно; музыка, маркеры, исходники и данные генераций сохраняются. При конфликте сохраняются и намерение, и предыдущая допустимая сборка; это не два независимо редактируемых проекта.

Изменение длины клипа через форму таймлайна даёт тот же последовательный сдвиг в сценарии. Перемещение клипа в том же сегменте меняет порядок; для явной паузы использовать соответствующее поле. Левая обрезка согласует вход в источник и паузу. Размещение из библиотеки сохраняет запрошенное начало, когда оно находится в свободном интервале.

↶/↷ на таймлайне отменяют/повторяют сценарные операции вместе с монтажом. Удаление использования/сегмента не удаляет исходные карточки, дубли или файлы. Созданная заготовка остаётся в библиотеке после отмены, чтобы материалы не пропали. Чужие несохранённые правки не перезаписываются: запись использует expected_revision; конфликт формы оставляет её текст доступным.

При перезапуске состояние сценария восстанавливается. Существующий проект не требует массового переименования или автоматического переноса Markdown-карточек. Сценарные описания отделены от промпта, заметок к дублям и авторского Plan.md.

## Агент и API

GET `/api/projects/{id}/scenario` — сценарий, вычисленные позиции, свободное время, issues и плановая проекция таймлайна; без записи и без GPU. POST туда же: expected_revision, actor, action, payload; ответ — полный новый проект. Неправильные поля/порядок/тип времени отклоняются, художественный конфликт бюджета сохраняется как видимый черновик.

| action | payload |
|---|---|
| add_segment | name, description='', start_frame=null, duration_frames=null, необязательный color |
| update_segment | id и изменяемые name/description/start_frame/duration_frames/color |
| remove_segment | id |
| reorder_segments | order: все ID сегментов ровно один раз; времена сохраняются |
| add_item | segment_id, title, description='', duration_frames=null, gap_before_frames=0; необязательные block_id (источник), index, take_id, source_in_frame |
| update_item | segment_id, id и изменяемые title/description/duration_frames/gap_before_frames/take_id/source_in_frame |
| remove_item | segment_id, id |
| reorder_items | segment_id, order: все ID блоков этого сегмента ровно один раз |

Времена API — целые кадры fps проекта; null допустим только для неизвестных начала/длины. Лимиты: 200 сегментов, 2000 использований, имя 160 и описание 12 000 символов, временные поля до 518 400 кадров. Исходный дубль обязан принадлежать выбранному источнику. Явное назначение старого видео может прочитать недостающие метаданные на CPU; чтение сценария и текстовые правки декодирование не запускают.

Локальный CLI:

```powershell
$studioPython = 'E:/ComfyUI_windows_portable/python_embeded/python.exe'
$studioAgent = 'E:/source/my/TOSAB/Book/TrueMoonTales/AMV/UI/studio_agent.py'
& $studioPython -s -B $studioAgent --project claire scenario
& $studioPython -s -B $studioAgent --project claire --actor agent:codex scenario --revision 7 --file '<путь к operation.json>'
```

operation.json содержит action и payload. Подставлять актуальную revision; при 409 перечитать состояние, без автоматического повторения записи. Контекст агента версии 2 дополнен сценарием/описаниями/конфликтами; подготовка и запуск видеогенерации по-прежнему отдельные действия.
