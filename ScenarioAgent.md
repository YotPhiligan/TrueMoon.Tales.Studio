# Подготовка и улучшение блоков с агентом — Studio 0.7

В карточке сегмента появились **«+ Блок с ИИ»** и **«Улучшить с ИИ»** у каждого блока. Они создают сохраняемое задание внешнему агенту. Автоматическая отправка в чат и встроенная модель пока не подключены; GPU-генерация остаётся отдельным действием.

## Работа из карточки

1. Для нового блока нажмите «+ Блок с ИИ»: укажите название, описание, примерную длительность и положение — в конце либо после выбранного блока. Неизвестную длительность можно оставить пустой. Для существующего нажмите «Улучшить с ИИ» на нужной карточке.
2. Введите запрос. Отметьте состав работы: описание действия, референсы, опорные кадры, промпт H3, настройки. Режим подготовки/изменения разрешает указанные обратимые правки; «Сначала предложить варианты» сохраняет предложение без изменения проекта.
3. Создайте задание. Оно появится в **«Задания агенту · этот сегмент»**. До исполнения новый источник/сценарный блок не создаётся.
4. Нажмите «Скопировать для чата», вставьте задание в чат с агентом и попросите выполнить его. Передаются адрес Studio, ID проекта/задания, запрос и снимок контекста. Доступ к localhost зависит от среды агента; локальному агенту предусмотрен CLI.
5. Агент берёт задание в работу, перечитывает проект и выполняет только запрос. Сохраняются окно сегмента, музыкальные опоры и исходные дубли. Нехватка времени показывается обычным конфликтом; скрытого ускорения или сдвига соседей нет.
6. Статус и фактический результат обновляются в карточке. **«Открыть результат»** открывает материалы созданного/изменённого блока. «Завершено» относится к запрошенному составу: текстовый черновик без изображений не становится готовым к генерации.

Задания можно просмотреть, скопировать и отменить. Отмена не откатывает уже выполненные правки; перед каждой записью агент перечитывает статус. Частичное/неудачное выполнение завершается через fail с описанием оставшейся работы. Задания и результаты сохраняются после перезапуска.

Контекст фиксирует сценарные segment_id/item_id и соответствующий block_id, описания, соседей, тайминг, музыку, референсы/Guides, дубли и документы. Описание сценарного использования отделено от H3-промпта источника. Один библиотечный источник может использоваться несколько раз: source_usage_count предупреждает агента о влиянии правки его материалов на другие использования. История и прежние дубли сохраняются.

## Конфликты и повторная отправка

Форма хранит исходную revision. При конфликте запрос остаётся на месте; **«Обновить контекст»** читает свежий проект, после чего запрос можно проверить и отправить повторно. Поздний ответ другого проекта/закрытой формы не заменяет текущее состояние.

Одна форма имеет client_key. Повтор той же отправки после обрыва ответа возвращает исходное задание со статусом. Изменённый запрос под использованным ключом отклоняется: проверьте список и откройте новую форму для другой задачи. Автоматического повтора записи нет.

## API и CLI

Прежние задания проекта/источника сохраняют контракт. POST `/api/projects/{pid}/agent/requests` принимает дополнительные scope и client_key:

```json
{
  "expected_revision": 16,
  "actor": "author",
  "goal": "Ускорить снижение, сохранив направление оружия",
  "mode": "apply",
  "scope": {
    "segment_id": "tseg-...",
    "item_id": "clip-...",
    "intent": "improve_block",
    "components": ["description", "prompt", "guides"]
  }
}
```

Для нового блока: intent=`prepare_block`, item_id=null, draft содержит title, description, duration_frames (целые кадры либо null), after_item_id (ID использования либо null для конца). Components: description, references, guides, prompt, settings. Снимок содержит request_scope, scenario_segment, scenario_item, ближайшие scenario_neighbors с исходниками. Сохраняется версия контекста 2 с добавочными полями. Свежий контекст: GET `/api/projects/{pid}/agent/context?segment={sid}&item={iid}`; item необязателен. При одновременном block он обязан соответствовать использованию. Чтение не пишет проект и не декодирует видео.

```powershell
$studioPython = 'E:/ComfyUI_windows_portable/python_embeded/python.exe'
$studioAgent = 'E:/source/my/TOSAB/Book/TrueMoonTales/AMV/UI/studio_agent.py'
& $studioPython -s -B $studioAgent --project claire requests
& $studioPython -s -B $studioAgent --project claire task --id 'req-...'
& $studioPython -s -B $studioAgent --project claire --actor agent:codex claim --id 'req-...' --revision 1
& $studioPython -s -B $studioAgent --project claire context --segment 'tseg-...' --item 'clip-...'
```

Подставляйте свежие ID/revision; --url перед командой задаёт другой порт. Request принимает --scope-file и --client-key. Сценарий/материалы меняются существующими scenario / patch-block с expected_revision. При propose проект не менять; при apply менять только выбранный состав. Перед каждой записью перечитать задание и уважать отмену. Наличие задания не разрешает GPU-запуск.

Finish нового блока в apply **обязан** передать --target-file с JSON `{"segment_id":"tseg-...","item_id":"clip-..."}`. Сервер проверяет сегмент и новое использование относительно снимка; добавляет block_id. Для improve ссылка может указывать только исходный item. Для propose ссылка на применённый результат не принимается.

```powershell
& $studioPython -s -B $studioAgent --project claire --actor agent:codex finish --id 'req-...' --revision 2 --result-file '<result.txt>' --target-file '<target.json>'
```

Сохраняются owner/revision, claim/finish/fail/cancel и запрет повторного завершения. Подготовку нельзя объявлять выполненной только по наличию путей без проверки фактических материалов.
