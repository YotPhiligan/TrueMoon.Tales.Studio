# STUDIO-BACKEND7 — CPU-экспорт MP4

Studio **1.2611.18.1-alpha**, TrueMoon **1.2611.17.1-alpha**, Enerit **protocol6**.
HTTPv1, schema2 и ProjectContractv1. Экспорт идёт в том же backend-процессе,
который читает проект и выполняет перенос и обрезку через единственный writer.
[HTTP-контракт](../../API.md#cpu-mp4-для-schema2).

## Настройка

Запустите `TrueMoon.Tales.Studio.exe --serve-project <копия-schema2> --config <config.json>`.
Возьмите URL и токен из ready JSON и задайте токен в `STUDIO_BACKEND_HTTP_TOKEN`.
Используйте конфигурацию с **отдельным** `exports_root` вне корней проектов,
медиаматериалов, legacy, защищённых каталогов и исходников Studio. На Windows
выберите короткий путь для временных файлов CPU worker. Ссылки и точки
повторной обработки в пути к хранилищу отклоняются.

С **1.2611.21.16-alpha** экспорт schema2, рабочий просмотр и аниматик
запускают C#-воркер из того же EXE. Укажите `ffmpeg_executable` и
`ffprobe_executable` или добавьте инструменты в `PATH`. Для экспорта
нужна сборка с libx264, AAC, PCM/WAV и стандартными аудио- и видеофильтрами.
Проверено на FFmpeg и FFprobe 9.0.2. Клиент выбирает путь для скачанного MP4.
[Конфигурация schema2 и запуск](BackendHttp.md#cli-и-запуск).

## Цикл задания в C# CLI

Запуск, статус, отмена и скачивание доступны из EXE начиная с
**1.2611.21.14-alpha**, явное восстановление — с **1.2611.21.15-alpha**.

Сначала прочитайте сохранённый проект через `backend-project`. Используйте
его `project.revision` и `fingerprint`. Создайте уникальный ключ из 16–80
ASCII-букв, цифр, знаков `_` и `-`. Команды ниже принимают `--url <url>`.

```text
.\TrueMoon.Tales.Studio.exe backend-export-start --url <url> --client-key <key> --profile project --revision <revision> --sha256 <project-sha>
.\TrueMoon.Tales.Studio.exe backend-export-status --url <url> --id <id>
.\TrueMoon.Tales.Studio.exe backend-export-download --url <url> --id <id> --sha256 <artifact_sha256> --output result.mp4
.\TrueMoon.Tales.Studio.exe backend-export-cancel --url <url> --id <id> --job-revision <status-revision>
.\TrueMoon.Tales.Studio.exe backend-export-recover --url <url> --id <id>
```

- `export-start` фиксирует exact-byte SHA и ревизию сохранённого проекта,
  профиль, расположение и параметры клипов, медиавходы и их SHA. Изменение
  проекта после приёма влияет на будущие задания. Worker сверяет SHA
  источников до и после рендера.
- `running` имеет ревизию 1. Успешное завершение даёт `completed` и
  метаданные размера, числа кадров, fps и `artifact_sha256`. Отмена меняет
  `running` на `stopping`, затем на `cancelled` после остановки.
  Устаревшая ревизия статуса вызывает 409, после которого нужно прочитать
  актуальный статус. При потере ответа CLI показывает ID для
  `backend-export-status`. Один активный CPU worker на `exports_root`.
- После перезапуска вызовите `backend-export-recover` с прежним ID. Backend
  сверит SHA запроса, сохранённый статус, доказательство завершения и байты
  MP4. Подтверждённый результат получает `completed` и доступен для скачивания.
  Прерванный рендер без подтверждённого результата получает `interrupted`,
  ранее завершённый с повреждённым MP4 — `failed`. Восстановление и повтор
  прежнего ключа обходятся без рендера. Для нового рендера нужен новый ключ.
- HTTP отдаёт байты только для `completed` с совпадающим SHA. CLI собирает
  файл из частей до 256 КиБ, проверяет размер и SHA-256, затем публикует новый
  файл в существующей папке. Существующий файл защищён от перезаписи.
  Квитанция возвращает ID, размер, SHA-256 и полный путь.

Типовые отказы HTTP — 409 при конфликте baseline, ключа или ревизии
статуса, 422 для неподдерживаемого монтажа, 429 при занятом CPU worker,
503 при недоступной конфигурации и 504 при дедлайне обращения. Ошибка
рендера после принятия задания видна в terminal status. Частичный MP4
не выдаётся клиенту.

## Область первой приёмки 18.11.2026

C# проецирует сохранённые placements schema2 в immutable request и
переиспользует CPU DraftRenderer для H.264/AAC. Первый срез покрывает монтаж
из нескольких клипов, чёрные паузы, обрезку и скорость, исходный звук,
музыку и звуковые события. Титры и переходы получают явный отказ. Лимиты
плана включают целочисленный FPS 1–120, 600 секунд материала, размер до
4096 по каждой стороне, 128 уникальных входов и 2 ГиБ входных данных.
Размер артефакта до 1 ГиБ. Время CPU worker ограничено 310 секундами.
Экспорт пишет в runtime-хранилище, состояние и история проекта остаются
доступны текущему writer.

Автоматизация использует отдельные временные проекты и короткие
синтетические MP4, запускает backend того же EXE через Mithril/Enerit и
обращается к нему через Kestrel и CLI. Проверяется состав кадров, H.264/AAC,
PCM, источники и результат по SHA, отсутствие записи проекта, остановка
активного worker и восстановление после жёсткой остановки backend.
Диалог C# UI, полная паритетная проверка титров и переходов и авторская
приёмка остаются в [плане](../../Plan.md#ближайшая-очередь).

## Воспроизведение

Задайте `STUDIO_TEST_FFMPEG` и `STUDIO_TEST_FFPROBE` на локальные
исполняемые файлы, а `STUDIO_BACKEND_EXE` на собранный или опубликованный
EXE текущей конфигурации. Для полного прогона с Web и Full Transfer также
задайте `STUDIO_TEST_PYTHON`. Тесты `BackendExportEndToEndTests`
создают и удаляют собственные проекты и процессы. В полном прогоне
используются `BackendExportPlanTests`, `BackendExportJobsTests`,
`BackendExportHttpContractTests` и Python `test_backend_export_cli`.

## Результаты 18.11.2026

Windows x64, Python 3.12.10, PyAV 18.1.0, FFmpeg и FFprobe 9.0.2. Обе сборки
с проверкой XML-документации прошли с 0 ошибок и 11 предупреждениями CS8669
в сгенерированном коде Enerit. В прежней поставке предупреждений этой
категории было 9.

| Проверка | Фактическое покрытие |
|---|---|
| 15 проверок плана | Layout, trim/speed, музыка и звуковые события, SHA источников, запрет недоверенных путей и неподдерживаемых проекций |
| 8 проверок заданий | Повтор ключа, различие baseline, ревизия отмены, поздний результат, пропавшее или повреждённое доказательство, recovery без запуска worker |
| HTTP-контракт | Права, метод, поля, типы, границы chunk и неизменность проекта |
| 3 сквозные | EXE/Mithril/Enerit → HTTP/CLI → PyAV/FFmpeg. 72 кадра с чёрными паузами и H.264/AAC, RMS звука, скачивание с SHA, отмена и жёсткая остановка, обнаружение повреждённого MP4 |
| 9 проверок CLI | Валидация параметров и ответов, отсутствие replay, скачивание несколькими частями, усечённый или повреждённый ответ и защита существующего файла |

Финальные Debug и Release — по 737 passed, 0 failed, 5 skipped.
Опубликованный EXE — 98 passed, 0 failed, включая все 3 сквозных
сценария экспорта и HTTP-контракт. SHA скриптов в publish совпадают
с исходниками, метка EXE — `1.2611.18.1-alpha`. Полный Python — 332 passed.

До правки остановки видео три полных прогона Release дали 1, 2 и 1 падение
соответственно. Все 27 сценариев экспорта прошли. Отказы были в raster
playback при seek и loss of focus с закрытым `PipesInvocationClient` или EOF.
Контрольная сборка `303ed21` завершила Release с 710 passed, 0 failed и
5 skipped. Пакет Enerit сбрасывает соединение, когда отмена прерывает запись
кадра в pipe. Studio теперь останавливает известное чтение видео через
`ClosePlayback`, оставляя записи RPC собственный дедлайн. Локальный stop
проверяется до команды чтения и после её ответа.

Промежуточные прогоны и контрольная сборка сохранены отдельно в
`src/.local/backend7-20261118-final/`. Пять прежних opt-in сценариев
пропущены в полных прогонах.

Финальные журналы, TRX, binlog, raster PNG, скрипт запуска и manifest
245 входных SHA сохранены в `src/.local/backend7-20261118-final2/`.
После проверки SHA всех входов совпали с manifest.
