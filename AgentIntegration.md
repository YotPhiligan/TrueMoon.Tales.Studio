Обновление Studio 0.7 / UI-03B: [подготовка и улучшение блока из карточки сегмента](ScenarioAgent.md), сценарная область/соседи, состав работы и ссылка на результат. Прежние задания проекта и источника ниже поддерживаются.

## Для автора

1. Перезапустить [Start-Studio.cmd](Start-Studio.cmd) после обновления Python и обновить страницу. Вверху должна быть версия 0.4; агент проверяет сервер командой doctor.
2. Нажать **«О проекте»** и заполнить замысел, стиль, требования непрерывности и рабочие указания агенту. Это рабочая карточка в Studio.project.json, а не новый источник канона книги. Plan.md остаётся отдельным документом.
3. Выбрать блок и открыть **«ИИ»**. Выбрать область — блок или весь проект — и режим: **«Предложить варианты»** либо **«Внести указанную правку»**. Описать задачу и нажать **«Создать задание»**.
4. У сохранённого задания нажать **«Скопировать»** и вставить в чат. Либо попросить локального агента взять конкретный ID из списка заданий выбранного проекта. Кнопка копирования текущего контекста также работает без создания задания.
5. Во вкладке «ИИ» наблюдать статусы «Ожидает агента → В работе → Завершено / Ошибка / Отменено». Результат доступен через «Подробнее». Изменения сохранённого блока появляются в редакторе автоматически, когда нет собственных несохранённых правок.

Пример сообщения: «В Studio, проект claire, выполни задание req-… в режиме предложения. Сначала прочитай свежий контекст и посмотри реальные опоры. Генерацию не запускай».

Отмена помечает локальное задание. Внешний агент обязан перечитывать статус перед следующим действием; сама отметка не прерывает чужой процесс или уже начавшуюся генерацию. Генерация останавливается отдельной кнопкой задания видео.

## Что получает агент

- Карточку проекта, revision, fps и размер; список исходных блоков и полный монтаж без undo/redo.
- Выбранный блок с промптом, ролями Picture, опорами, настройками, технической проверкой и дублями.
- Все использования блока на шкале и их фактических предыдущего/следующего соседа, включая соседей из других сегментов. Порядок библиотеки не подменяет монтаж.
- Пути и локальные media URL изображений/видео/музыки, сведения о доступности файлов, источник Motion Context с native AV/последним PNG. Для latent даётся путь; он не объявляется воспроизводимым медиа.
- Документы из фиксированного списка: корневой/AMV/проектный AGENTS.md, общий/проектный Plan.md и исходная карточка блока внутри каталога проекта. Для текста — роль, SHA256 и явная отметка обрезки. До 12 000 символов на документ; при обрезке нужный документ читается целиком по указанному пути. Handbook.Secrets.md автоматически не включается.

Снимок контекста имеет SHA256. Путь или метаданные не доказывают, что агент посмотрел видео/изображение или прослушал звук. Рабочие планы и карточки не отменяют пользовательские инструкции и источники канона.

Для заданий, в которых агент готовит изображения, референсы или визуальную
часть промпта, открыть
[визуальный стиль цикла](../TrueMoon.Tales.Arts/AGENTS.md#визуальный-стиль-цикла).
Сверить его с фактическими опорами и замыслом выбранного проекта.

## Командный помощник

Все команды из корня книги, portable Python уже установлен. Глобальные аргументы указываются **до** имени команды. Токен получается в памяти при записи, не сохраняется в файл и не выводится doctor.

```powershell
$studioPython = 'E:/ComfyUI_windows_portable/python_embeded/python.exe'
$studioAgent = 'E:/source/my/TrueMoon.Tales/TrueMoon.Tales.Studio/studio_agent.py'
& $studioPython -s -B $studioAgent doctor
& $studioPython -s -B $studioAgent projects
& $studioPython -s -B $studioAgent --project claire requests
& $studioPython -s -B $studioAgent --project claire context --block CL-002A
```

Если сервер использует другой порт, добавить `--url http://127.0.0.1:ПОРТ`. Помощник работает с локальным HTTP; для внешнего агента без доступа к этому компьютеру передаётся скопированный контекст, а доступ к API сам по себе не появляется.

Чтение задания, взятие в работу и свежий контекст:

```powershell
& $studioPython -s -B $studioAgent --project claire task --id req-0123456789abcdef
& $studioPython -s -B $studioAgent --project claire --actor agent:codex claim --id req-0123456789abcdef --revision 1
& $studioPython -s -B $studioAgent --project claire context --block CL-002A
```

Здесь `--revision 1` — версия **задания**, не проекта. Снимок в task показывает исходное намерение; перед записью получить свежую revision проекта и проверить актуальность источников. Взятие задания не закрепляет и не блокирует проект для автора.

Для правки передать UTF-8 JSON-файл только с нужными редактируемыми полями блока, например notes или prompt:

```powershell
& $studioPython -s -B $studioAgent --project claire --actor agent:codex patch-block --block CL-002A --revision 7 --file '<абсолютный путь к patch.json>'
& $studioPython -s -B $studioAgent --project claire --actor agent:codex finish --id req-0123456789abcdef --revision 2 --result-file '<абсолютный путь к result.txt>'
```

`--revision 7` здесь — актуальная версия **проекта**; `--revision 2` — задания после claim. Подставлять фактические значения. `finish`/`fail` требуют непустой UTF-8 отчёт: что сделано, какие файлы/поля изменены, что проверено и что осталось ограничением. В режиме propose проект не менять; сохранить предложение как результат задания. Режим apply разрешает только правку из пользовательской задачи и сам по себе не разрешает запуск GPU.

Также доступны brief (чтение; запись через --file/--revision), request (--goal-file/--mode/--revision/необязательный --block), cancel, fail, continue (--block/--take/--revision), prepare (--block/--revision), job (--id), launch (--id), stop (--id). `continue` создаёт черновик. `prepare` собирает граф. **Только явный launch запускает дубль**; применять его при соответствующем запросе автора, без повторного запроса уже данного разрешения.

Записи автоматически не повторяются. При 409 помощник завершает работу с кодом 3: перечитать состояние и согласовать пересечение, сохранив правки автора. При сетевом сбое сначала проверить состояние прежнего задания/проекта; не создавать второй GPU-запуск вслепую. Другие ошибки дают код 1, успешная команда — 0. Команды статуса возвращают компактный ответ; task/context — полный снимок.

## Хранение и API

Карточка — поле brief в корневом Studio.project.json, с общей revision/историей. Для старого проекта пустая карточка вычисляется при чтении без записи миграции.

Задания — Production/AgentRequests/req-….json. У каждого собственные revision, mode, owner, goal, state, result и неизменный снимок контекста. Создание/смена статуса не меняют revision проекта, не готовят workflow и не запускают GPU. Автор/actor — метка происхождения, не отдельная учётная запись или система разграничения прав. Задания сохраняются после перезапуска.

| API | Назначение |
|---|---|
| GET /api/projects/{id}/brief | Карточка; без записи |
| PATCH /api/projects/{id}/brief | expected_revision проекта, brief с изменяемыми полями, actor |
| GET /api/projects/{id}/agent/context?block={ID или точный label} | Контекст блока; без block — обзор проекта |
| GET /api/projects/{id}/agent/requests | До 200 последних заданий без тяжёлого context |
| POST /api/projects/{id}/agent/requests | expected_revision проекта, goal, mode=propose/apply, необязательный block_id, actor |
| GET /api/projects/{id}/agent/requests/{request} | Задание и исходный context |
| POST /api/projects/{id}/agent/requests/{request} | expected_revision задания, action=claim/finish/fail/cancel, actor, result |

Для записи действуют прежние Host/Origin/token-проверки. Claim возможен только из pending; finish/fail — из running тем же owner. Одновременный claim имеет одного победителя. Терминальное задание не открывается повторно; для следующей итерации создаётся новое. Goal/поля brief — до 12 000 символов; actor — до 80, result — до 100 000. Имеющийся API блоков/таймлайна/генерации и legacy /context сохранены.
