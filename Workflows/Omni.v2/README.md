# Omni v2: Draft и Full Transfer

29.10.2026. Отдельная кандидатная ветка R-08. Два профиля собраны из выполненных PV01/PV03; их новые UI/API-графы прошли штатную CPU-валидацию. В [PT01](../../Research/Results/R-05.PT01.PromptOrder.v1/Report.md) выполнены три API Draft с реальным GPU и collect, сохранены Raw/последний PNG, логи и сравнение. Full Transfer этого ядра и импорт/экспорт нового UI в браузере ещё не проверены. [Подготовительный отчёт](../../Research/Results/R-08.DraftTransfer.v2/Report.md).

| Профиль | Выход | Входы движения |
|---|---|---|
| Draft | 896 × 512 | Изображения и один первый Guide 0 |
| Full Transfer | 1280 × 736 | Те же роли изображений, первый Guide 0 и явно выбранный MP4 как Video 1 |

В обоих профилях: Omni NVFP4 QAD, Qwen NVFP4 AWQ, установленные FP16 video / FP32 audio VAE, `res_multistep/simple`, 8 шагов, BasicGuider, shifts 12/3, SageAttention, `fp16_accumulation`, native dynamic VRAM. Все custom nodes отключены. Аудио VAE обслуживает внутреннее устройство H3; выходной файл без звука. Из GetVideoComponents подключён только IMAGE batch: звук и fps видеореференса не передаются в conditioning или выход.

Изображения идут в порядке массива `references`: Picture 1, Picture 2 и далее. `guides[0].picture` выбирает одно из этих изображений и дополнительно подключает его как первый кадр. Отдельный портрет/полный рост не становится сценической опорой сам по себе.

## Готовые примеры

- [Draft.json](Examples/Draft.json) и [точный промпт PV01](Examples/Draft.Prompt.txt).
- [FullTransfer.json](Examples/FullTransfer.json) и [точный промпт PV03](Examples/FullTransfer.Prompt.txt).
- UI-файлы для просмотра: [Draft](Profiles/Draft.v2.json), [Full Transfer](Profiles/FullTransfer.v2.json). Они ссылаются на уже подготовленные входы примеров.

Это технические примеры Клэр: локация → костюм ниже воротника → карабин → собранная первая опора. В Full Transfer выбран существующий PV01, поскольку для него уже есть согласованный текст фаз. Этот дубль не утверждён для монтажа: длинная выдержка и колебания высоты намеренно сохраняются в примере переноса.

Для другого блока скопировать JSON и TXT в его рабочую папку, задать новый `id`, пути и роли изображений, номер первой опоры, `seconds`, `seed`, промпт. Относительные пути разрешаются от папки JSON. У Full Transfer отдельно выбрать `motion_video.path`, описать назначение в `role` и фактические фазы в `review_notes`. Подготовка требует эти поля, но смысловое соответствие изображения, текста и движения проверяет человек/агент при просмотре.

Промпт содержит шесть разделов Ref2VA. Номера Picture обязаны совпадать с порядком изображений. Только Full Transfer использует `<Video 1>`; оба звуковых поля — `N/A`. При смене выбранного видео обновить определения, summary, retention_analysis и фазы detailed_description под его реальное движение. Автоматического переписывания текста или отбора дубля нет.

## Подготовка, проверка, отдельный запуск

Использовать portable Python; общий модуль явно подключается даже при изолированном `python_embeded`. Пути ComfyUI/Python в этом кандидате привязаны к текущей portable-установке.

```powershell
$pipe='E:\source\my\TOSAB\Book\TrueMoonTales\AMV\Workflows\Omni.v2'
$python='E:\ComfyUI_windows_portable\python_embeded\python.exe'
$config="$pipe\Examples\Draft.json"
$job='E:\source\my\TOSAB\Book\TrueMoonTales\AMV\Research\Results\MY-SHOT.Draft.Run01'

# Без --stage: только файлы задания; запуск такого задания запрещён.
# С --stage: также проверенные копии в input ComfyUI. Очередь не используется.
& $python -s -B "$pipe\prepare.py" $config $job --stage
if ($LASTEXITCODE) { throw 'Preparation failed' }

# Только CPU, максимум 90 секунд; выходит до GPU-сервера.
& "$pipe\run.ps1" -JobDir $job -ValidateOnly
```

Для запуска одного дубля отдельно выполнить:

```powershell
& "$pipe\run.ps1" -JobDir $job -Mode api
if ($LASTEXITCODE) { throw 'One take failed; inspect logs, no automatic retry' }
& $python -s -B "$pipe\collect.py" $job
```

Вариант `-Mode ui` поднимает собственную ограниченную ComfyUI на `http://127.0.0.1:8199`. Открыть сохранённый `R08.Current.json` в её списке workflow и один раз нажать Run. Ожидание нажатия — до 300 с; экспорт должен совпасть с подготовленным API. Изменять входы/промпт следует в JSON/TXT и готовить новое задание. Профили в обычной пользовательской ComfyUI сами таймеров не добавляют.

Каждый новый дубль — новый каталог задания. Подготовка отказывает, если каталог существует. Запуск сохраняет эксклюзивный Launch.claim; HTTP-guard сравнивает API и принимает максимум один запрос на `/prompt` или `/api/prompt`, включая переключение между адресами. Submission.claim/Submission.json фиксируют попытку до выполнения; не удалять их для повтора. При неопределённом исходе сначала прочитать логи/History, затем готовить новый дубль.

Оба прохода не объединены в автоматическую очередь. Сначала сгенерировать и просмотреть Draft. Только выбранное видео передать в новое задание Full Transfer с обновлённым промптом и теми же согласованными ролями изображений. Низкое разрешение меняет саму генерацию; перенос может сохранять ошибки исходной динамики и не даёт гарантии точного покадрового повторения.

## Контракт и диагностика

- Длительность 2–8 с округляется вверх на сетку `17k+5` при 24 fps. `seconds: 2.0` → 56 кадров → 2,333… с; последний PNG — индекс 55. Ограничитель не обещает уложить любой 8-секундный блок в текущий GPU-дедлайн.
- Видеореференс — один MP4, постоянные 24 fps и ровно столько кадров, сколько у округлённого выхода. Его кадры декодируются при подготовке на CPU. Скрытого retime/обрезания нет. Наличие аудио записывается; аудиопорты отключены.
- Разрешено 1–8 упорядоченных изображений. Проверенный пример использует четыре. Этот кандидат поддерживает только один Guide 0; последние/промежуточные Guides и перенос на другие количества референсов здесь отдельно не тестировались.
- Build.json — manifest: конфигурация, роли, исходные и staged пути/хэши, параметры времени/разрешения, metadata MP4, хэши API/UI/TXT/Job и кода, размеры/mtime моделей. Большие веса повторно не хэшируются.
- Preflight перед запуском проверяет исходники, staged копии, код, графы и промпт. После изменения кода или входов требуется заново подготовленное задание.
- CPU preflight 90 с; старт 90 с; генерация 480 с; отсутствие обновления Runtime 180 с; общий предел 720 с плюс завершение. Независимый watchdog сверяет PID, время создания, exe и команду своего сервера. Чужие процессы не завершаются. Таймер не предотвращает системный BSOD.
- Сохраняются Prompt/API/UI, manifest, Validation, Submission/History, Runtime, телеметрия, watchdog/cleanup, Raw MP4, последний PNG. `collect.py` проверяет результат, fps/размер/число кадров/отсутствие аудио, конечность H3 и работу Sage, создаёт Contact.png и Result.json. Автоматического статуса «принято в монтаж» нет.

Общее [Omni.v1](../Omni.v1/README.md) сохранено. Для продолжения через native AV latent / Motion Context использовать его проверенную цепочку. V2 Draft/Full Transfer не сохраняет native AV и не заменяет это продолжение. Текущая ветка также не добавляет звук, ControlNet или base H3.

## Происхождение и статус

Локальные Templates содержат копии выполненного PV03 API/UI и определений ImageFromBatch/SaveImage из MC01.A. Подготовка не зависит от запуска исследовательских скриптов. Runtime/драйвер/watchdog перенесены из Omni.v1 с отключением custom nodes, усилением guard для API и UI и атомарной записью подачи. Скрипт build_runtime.py из старого ядра не запускается.

Подтверждены два первоначальных native CPU-preflight, эквивалентность генерационной части PV01/PV03, 429 проверок структуры/контрактов и фиктивного обработчика, отдельная проверка watchdog. Затем PT01 подтвердил три API Draft → bounded run → collect на GPU: 42,502 / 42,583 / 42,092 с, по 400 Sage / 0 SDPA, 56 кадров и последний PNG, собственные серверы остановлены. Явного улучшения ранней хореографии у двух изменённых промптов нет; это техническая интеграция, не монтажная приёмка. Full Transfer и браузерный UI нового ядра остаются следующими отдельными проверками, без автоматического запуска.
