# Omni v1 — общий workflow «Сказок истинной луны»

29.10.2026. Первый общий комплект R-08. Рабочая основа: **FastH3 Omni NVFP4 QAD + Qwen3-VL-32B NVFP4 AWQ**, установленные FP16 video VAE / FP32 audio VAE, Sage + fast fp16_accumulation + native dynamic VRAM. Дополнительные модели и пакеты не устанавливались.

Два профиля одного ядра:

| Профиль | Назначение | Результаты |
|---|---|---|
| `omni-guided` | Новый отдельный шот с упорядоченными картинками и сценическими Guides | Raw MP4, последний PNG до MP4, точный парный AV-latent |
| `omni-context` | Продолжение того же плана из сохранённого AV-latent | Те же исходники и отдельный New MP4 после trim 22 |

Для смены ракурса ставить новый шот. Motion Context сохраняет часть предыдущего движения, но не гарантирует бесшовность и правильную хореографию. Видео и готовые шаблоны этого опыта не приняты в монтаж автоматически. [Отчёт R-08](../../Research/Results/R-08.Pipeline.v1/Report.md).

## Быстрый ручной путь

1. Открыть `run_manual_omni.bat` в этом каталоге. Он запускает установленную portable ComfyUI с Sage и только пакетом Motion Context. Другие запуски Comfy предварительно завершить обычным способом; скрипт не управляет чужими процессами.
2. Загрузить один из [готовых UI-графов](Profiles/): `Omni.First.v1.json`, `Omni.Calm.TwoGuides.v1.json` или `Omni.Continue.v1.json`. Это примеры с реальными ассетами Клэр; заменить содержимое узлов Picture и промпт под новый шот.
3. Роли подписаны в заголовках Picture: локация, взрослый персонаж/костюм, поза, предмет, сценическая опора. Порядок Picture N в промпте должен совпадать с фактическими входами. Один арт может выполнять несколько ролей; отдельные картинки для каждой роли не обязательны.
4. Отдельно выставить длительность, seed и имена вывода. Сохранять seed фиксированным для сравнения. Назначение и индексы Guides проверять по изображению и фактической длине, а не только по имени файла.
5. Для продолжения загрузить точный AV-latent предыдущего блока через Load Latent, сохранить парный формат. В примере используется `folder=input`, файл подготовлен автоматически; для ручного файла из стандартного output выбрать `folder=output` и корректный путь. `clip_index` загрузки > 0, индекс сохранения следующего блока увеличивается. Picture границы заменить последним PNG предыдущего блока.
6. Сохранять Raw и New раздельно. Для профиля Context подключён `trim_frames` из узла Motion Context; не убирать дублированные 22 кадра второй раз.

Ручной сервер позволяет редактировать граф и отправлять задания обычным способом. **Защитные таймеры и запрет повторной отправки действуют в отдельном ограниченном пути ниже.** Сам batch-launcher не превращает произвольную ручную очередь в ограниченную.

## Ограниченный воспроизводимый путь для автора и ИИ

Редактируется JSON задания, затем создаётся новая уникальная папка результата. Пример: [Action.First.json](Examples/Action.First.json), спокойный вариант — [Calm.json](Examples/Calm.json). Промпт хранится отдельным UTF-8 TXT.

```powershell
$omniPipe='E:\source\my\TOSAB\Book\TrueMoonTales\AMV\Workflows\Omni.v1'
$omniPython='E:\ComfyUI_windows_portable\python_embeded\python.exe'
$omniJob='E:\source\my\TOSAB\Book\TrueMoonTales\AMV\Research\Results\MY-SHOT.Run01'
& $omniPython -s -B "$omniPipe\prepare.py" "$omniPipe\Examples\Action.First.json" $omniJob --stage
& "$omniPipe\run.ps1" -JobDir $omniJob -Mode api
& $omniPython -s -B "$omniPipe\collect.py" $omniJob
```

`prepare.py` без `--stage` только собирает документы; с `--stage` копирует входы в Comfy input и проверяет существующие копии. **Ни один режим подготовки не ставит задание в очередь.** Команды `run.ps1 -Mode api` и нажатие Run при `-Mode ui` выполняют генерацию.

Перед запуском читаются хэши подготовленных входов, API, UI-графа и текста; далее выполняется штатная CPU-валидация Comfy. Используются отдельный скрытый сервер 8199, собственные output/temp/user. Если 8199 занят или пользовательская очередь 8188 непуста, запуск прекращается. Остановить разрешено только созданный этим запуском сервер; watchdog проверяет PID, executable, command line и время создания.

Одна папка задания → максимум одна отправка. При наличии `Submission.json` launcher отказывается повторять задание. Для другого дубля создать новый id/каталог. Старые результаты сохранять. Первый UI-контроль выявил необходимость проверять **оба** адреса `/prompt` и `/api/prompt`; повторная отправка на них проверена отказом 409.

Таймеры: CPU validation 90 с, startup 90 с, ожидание ручного UI-старта 300 с, генерация 480 с, отсутствие Runtime-обновлений после отправки 180 с, весь запуск 720 с плюс короткое завершение. Срабатывает наиболее ранний применимый предел. Автоматического повторения генерации нет; пределы процессов не предотвращают BSOD.

Для UI-проверки использовать `run.ps1 -Mode ui`, открыть `http://127.0.0.1:8199`, выбрать `R08.Current` в «Рабочих процессах» и нажать «Запустить» один раз. Сервер сравнивает экспорт с подготовленным API; различия блокируются до очереди. Поэтому изменения входов внутри этого ограниченного UI-сеанса требуют повторной подготовки в новой папке. Обычное ручное редактирование доступно через `run_manual_omni.bat`.

## Поля задания

| Поле | Что задавать |
|---|---|
| `id` | Новое короткое имя без разделителей каталогов |
| `profile` | `omni-guided` или `omni-context` |
| `references` | Упорядоченный список `role` и `path`; порядок определяет Picture N |
| `guides` | `picture` — номер Picture; `frame` — индекс либо -1 для последнего |
| `prompt` | Путь к TXT с шестью разделами Ref2VA |
| `size` | Ширина/высота, кратные 32; проверенный рабочий размер 1280 × 736 |
| `seconds` | Желаемая исходная длина; фактическое число кадров записывается в Build |
| `seed` | Фиксированный seed для контрольного дубля |
| `previous_latent` | Только для Context: точный парный AV safetensors предыдущего блока |
| `clip_index` | Номер сохраняемого блока; 1 для первого, 2 и далее для продолжений |

Подготовщик проверяет номера Picture, порядок шести разделов и совпадение числовых входов; **смысловое соответствие референсов тексту проверяет автор/ИИ**. При изменении порядка картинок переписать все затронутые метки в промпте. Общая структура соответствует [официальному Ref2VA-гайду](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md).

Длительность: формула текущего графа округляет к сетке `17k+5` при 24 fps. `4.0` → 107 кадров / 4,4583 с; `5.0` → 124 / 5,1667 с. Context 124 → New 102 / 4,25 с. Монтажное окно задаётся отдельно. Разрешённый в подготовщике диапазон 2–8 с — защитное ограничение v1, а не подтверждение качества всех длин; испытанные примеры указаны в отчёте.

## Продолжение из результата

```powershell
$omniNextConfig="$omniPipe\Examples\MY-SHOT.Continue.json"
& $omniPython -s -B "$omniPipe\continue_from.py" $omniJob $omniNextConfig --id MY-SHOT.B --prompt "$omniPipe\Examples\Action.Continue.Prompt.txt" --anchor-picture 5
```

Эта команда **не генерирует**: получает native latent и последний PNG из успешного History, сохраняет их SHA256 и создаёт следующий config. Номер Picture границы задаётся явно; роли остальных картинок сохраняются. Пример использует существующий учебный промпт движения у парапета — для иного содержания его нужно переписать, не запускать вслепую. Затем снова вызвать `prepare.py` в новой папке и `run.ps1`.

## Что сохраняется и что ещё не включено

Каждое задание сохраняет config, точный промпт, упорядоченные входы и хэши, UI JSON, отдельный API JSON, штатную Validation, Submission/History, Runtime, телеметрию памяти, watchdog/cleanup, Raw, lossless PNG и AV-latent; Context добавляет New. `collect.py` проверяет кадры/fps, отсутствие аудио и наличие двух потоков в latent, делает контактные листы и Result.json.

v1 выпускается с беззвучным выходом. Native AV внутри H3 и контекста сохраняется. Речь, синхронный эмбиент, RefPack без Guides, внешнее motion-video, Depth/Pose/Canny, базовая H3 и альтернативные веса остаются отдельными исследовательскими ветками. Они не спрятаны за переключателями непроверенной совместимости. Полный перенос на опенинг и длинная цепь продолжений ещё не подтверждены. После этого первого R-08 основной технический приоритет — управляемость движения R-04.
