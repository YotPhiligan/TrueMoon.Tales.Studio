# Omni v1.1 — native AV / Motion Context и запись диагностики Windows

30.10.2026. Добавочная версия [Omni.v1](../Omni.v1/README.md), прежнее ядро сохранено. Схема моделей, prepare, входы и sampling не изменены.

- server.py взят из проверенной MC02 RecoveryRuntime: сериализация persist, ожидание краткой блокировки замены Runtime.json до 2 с, отдельный snapshot вместо срыва GPU-результата при исчерпании ожидания. В MC02 проверены краткая блокировка и один GPU-проход; в MC03 — также реальный non-fatal fallback после 2 с и два API-прохода.
- run.ps1 перед стартом вызывает port_guard.py: проверяет TCP-соединение и исключительное занятие 8199, сверяет таблицу владельцев; активного слушателя сохраняет и прекращает запуск. При занятом порте без отвечающего владельца ждёт освобождения до 45 с; весь helper ограничен снаружи 60 с. Это предзапуск, до общего таймера 720 с. Остальные таймеры и независимый watchdog прежние. В MC03 таблица psutil пропустила синтетический live listener, поэтому она не используется как единственное доказательство свободного порта.
- Никаких автоматических повторов или остановки чужого процесса. Пользовательский launcher/очередь и portable custom nodes не изменяются.

Входы и API/UI-файлы подготавливаются как в v1. run.ps1 получает отдельный JobDir, после него collect.py проверяет реальные выходы. [MC03](../../Research/Results/R-01.MC03.EndGuide.v1/Report.md) завершил два API → GPU → collect с native AV, Raw/New и PNG, 400 Sage / 0 SDPA, конечными forward и остановкой своих серверов. Проверен Context без/с последним Guide. Браузерный UI новой версии, длинная цепь и специально зависший GPU остаются отдельными проверками.

build_runtime.py не копировался: старый генератор обвязки не содержит исправления и не должен перезаписывать эту версию. UI-примеры прежнего ядра остаются в Omni.v1/Examples. Новый UI-путь v1.1 отдельно не проверялся.
