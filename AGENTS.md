# Работа над TrueMoon Tales Studio

Назначение: приложение видеопродакшена, локальный API/CLI, UI, тесты и общая
интеграция ComfyUI. [README](README.md), [общие инструкции](../TrueMoon.Workspace/Guidelines.md),
[план переноса](../TrueMoon.Workspace/MIGRATION.md).
[Карта проектов](../TrueMoon.Workspace/Projects.md).

Перед задачей в общей рабочей области явно прочитать документы Workspace по ссылкам
выше, затем применимые правила этого файла и вложенных AGENTS.md. Наличие ссылки
не означает, что её содержимое уже прочитано. Если открыт отдельный клон/worktree,
найти Workspace в подтверждённой основной рабочей области; пути к материалам не угадывать.
При автономной разработке публичного клона Studio без соседнего Workspace следовать
локальным правилам этого файла; доступ к материалам и лору подключать только по
подтверждённым внешним путям. Отсутствие частных материалов не мешает самодостаточной
технической задаче, которой они не нужны.

В этом репозитории находится активный код Studio 0.15 после M2. Перед технической
задачей читать [README](README.md), [Workspace](Workspace.md),
[Architecture](Architecture.md), [Plan](Plan.md), [Status](Status.md), API и нужный проверочный отчёт.
Старая UI 0.14 в Book сохранена как исходный архив; новые правки кода выполняются
только здесь. Проекты Клэр/опенинга перенесены в Videos в M4.

Соседний `TrueMoon` развивается параллельно: в миграционных задачах не перемещать,
не копировать, не исправлять и не восстанавливать его файлы. Проверять Git только
чтением с `--no-optional-locks`; изменения другой работы не считать поломкой.
Studio исключает этот каталог из доступа через resolver.

- Сохранять разделение кода и пользовательских данных: проекты — Videos,
  общие референсы — Arts, тексты/лор — внешние источники, runtime state/cache отдельно.
- При поддержке внешних корней сохранять allowlist путей, ограничение записи,
  expected_revision, атомарное сохранение, историю и защиту конфликтного черновика.
- Перенос сохраняет существующие ID/связи/тайминги и immutable снимки. Не менять
  авторские проекты/генерации, чтобы упростить тест или получить чистый Git.
- Подготовка workflow не отправляет очередь; чтение/запуск UI не запускают GPU.
  Prepare/launch/collect, таймеры/watchdog, проверка владения процессами и
  восстановление без повторной отправки сохраняются.
- Изменения preview/монтажа проверять с учётом соответствия CPU MP4: участки,
  скорости, звук, переходы, кириллица/титры. Использовать отдельный тестовый проект.
- GPU, длительные/аппаратные проверки и установка моделей требуют соответствующего
  запроса; не занимать чужие порты/очереди и не закрывать пользовательские процессы.
- Тесты/синтаксис/ссылки выбирать по изменению. Старые отчёты описывают прошлую
  конфигурацию, а не доказывают работоспособность после переноса.
- После завершения этапа обновлять Status.md с результатом и границами проверки. План и критерии вести в Plan.md.
- Код остаётся Python/JS до отдельного
  технического решения; наличие C# фреймворка не является миграцией реализации.

## M4 · Book отключён

Видео/Production/исследования находятся в TrueMoon.Tales.Videos. Конфигурация
`legacy_read_enabled: false` оставляет legacy_root только логическим пространством
старых имён: стат/чтение/запись туда запрещены, unmapped пути возвращают 403.
Aliases перенаправляют относительные и абсолютные старые строки до файлового IO.
Экспорт получает только реальные новые пути. Исторический prepared с config в старом
пространстве имён возвращает 409 без запуска/мутации; подготовить свежий дубль.
Новые prepare/launch работают с новыми физическими путями. Исторические снимки
не переписываются. Для применения конфигурации перезапустить Studio.


## Arts · категории в корне

Библиотека TrueMoon.Tales.Arts использует Characters/, Props/ и другие категории
сразу в корне. Mount @arts указывает на корень репозитория; пример нового адреса:
@arts/Characters/Claire/ComfyUI_00915_.png. Конфигурация сохраняет aliases для
старого @arts/Arts/... и прежнего Book/Arts/... без переписывания ID/истории.
После обновления Studio.config.local.json перезапустить уже открытый сервер Studio.

## Ограничения TrueMoon и заявки владельцам модулей

При обнаружении ограничения/недостающей возможности сначала сверить API текущего
пакета, исходники, план модуля и существующие запросы. Подтверждённую потребность
фиксировать в плановом контуре TrueMoon отдельной заявкой по
[правилам requests](../TrueMoon/src/docs/requests/README.md), с примером из Studio,
критериями готовности и влиянием на текущую задачу. В Plan/Status Studio сохранять ссылку.
Непроверенный сценарий не объявлять дефектом, существующую задачу не дублировать.

Параллельная разработка TrueMoon продолжается: автор заявки публикует новый
уникальный Request/Notes, владелец модуля принимает через эксклюзивный Claim и
Decision и ведёт реализацию в своём PLAN. Общие планы и чужие незакоммиченные
изменения сохранять; перед записью сверять актуальный SHA. Добавление заявки
не разрешает менять код движка или перехватывать задачу другого агента.

## Жизненный цикл проверочных процессов

Проверочные Python-серверы, native UI и вспомогательные процессы не оставлять
после задачи. Для изолированных проверок окна использовать управляемый запуск
`src/Verification/WindowMenusQA.py --ui <exe>` по [инструкции QA](src/QASessions.md).
Не запускать QA-сервер через прямой `app.py` и окно отдельным бесконтрольным
`Start-Process`: оба процесса должны принадлежать одной ограниченной сессии.

До запуска сверить `--status`, сохранить ID новых сессий и tool session IDs.
У запуска должны быть дедлайн, журнал и владелец; очистка — в `finally`, включая
ошибку старта, отмену и таймаут. Перед финальным ответом остановить свои сессии
через `--stop <id>`, дождаться завершения tool sessions и проверить отсутствие
принадлежащих задаче процессов. Для новых QA-сессий Windows Job Object завершает
всех потомков и при аварии контроллера; время жизни по умолчанию 15 минут.

Не считать номер PID доказательством владения: сверять exe, команду и время
создания, а при остановке исключать повторное использование PID. Старые запуски
вне registry проверять отдельно. Не завершать все `python`/`ffmpeg` по имени,
пользовательские приложения, ComfyUI и сессии другого агента. `--stop-all`
применять только при явном запросе на общую остановку. Оставлять окно/сервер
после задачи можно только по явному запросу пользователя с указанием ID и срока.
