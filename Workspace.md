# Внешние каталоги после M4 · Studio 0.15

Код Studio принадлежит `TrueMoon.Tales.Studio`. Проекты Клэр и опенинга,
Production/история и исследования находятся в `TrueMoon.Tales.Videos`. Библиотеки
Arts/Lore/Texts подключены извне. Чтение Book отключено; старые имена разрешаются
через aliases до файлового доступа. ID и immutable снимки сохранены.

## Настройка и запуск

Скопировать `Studio.config.example.json` в `Studio.config.local.json`, проверить
пути и запустить `Start-Studio.cmd`. PowerShell 7 читает `python_executable` из
конфига; сам сервер запускается portable Python. Установка пакетов не выполняется.
Другой конфиг задаётся `Start-Studio.ps1 -Config <файл>` или переменной
`TRUE_MOON_STUDIO_CONFIG`; `STUDIO_PYTHON` меняет Python запуска приложения.
Для подготовки/генерации профиль использует `python_executable` из конфига.

```powershell
# Из корня репозитория Studio. Только проверка, GPU не запускается.
& 'E:/ComfyUI_windows_portable/python_embeded/python.exe' -s -B ./app.py --check
# Другой порт, без открытия браузера:
./Start-Studio.ps1 -Port 8788 -NoBrowser
```

Если порт занят, запуск сообщает ошибку и оставляет существующий процесс в покое.
Для переключения со старой версии пользователь останавливает прежний сервер и
запускает новый launcher. Одновременная запись двух Studio в один проект не нужна.
API `GET /api/workspace` показывает фактически загруженные корни и политику доступа.

## Поля конфигурации v1

Все относительные пути конфигурации считаются от самого JSON. Поддерживаются
абсолютные пути и переменные окружения. Неизвестные поля/версии отклоняются.

| Поле | Назначение |
|---|---|
| legacy_root / legacy_read_enabled | Пространство старых имён Book; чтение выключено после M4 |
| amv_root | Активный корень TrueMoon.Tales.Videos |
| projects_root | Новые проекты; именованный путь `@projects/<id>` |
| mounts | Библиотеки `@arts/`, `@videos/`, `@lore/`, `@texts/`; по умолчанию только чтение |
| state_root | Реестр Studio; вне кода и вне проектов |
| cache_root | Производные волны/звуковые превью/слои титров; без изменения проекта |
| exports_root | Новые CPU-экспорты; прежние экспорты доступны на старом месте |
| project_write_roots | Явные рабочие каталоги существующих проектов; Production существующих проектов в Videos |
| profiles_root | Исполняемый профиль; в 0.15 — Workflows/Omni.v1.1 |
| python_executable / comfy_root | Установленная среда и ComfyUI; ничего не скачивается |
| protected_roots | Каталоги, запрещённые для чтения и записи Studio |
| path_aliases | Совместимость старого префикса с новым каталогом после согласованного переноса |

`@studio`, `@profiles`, `@state`, `@projects`, опциональные `@cache` и `@exports`
зарезервированы. Настройка `mounts` не даёт права записи. Выход через `..`,
абсолютный хвост именованного пути и обход через symlink/junction отклоняются.
Защищённый соседний `TrueMoon` исключён автоматически относительно корня кода,
даже при использовании внешнего конфигурационного файла. Записываемый корень,
пересекающийся с ним, запрещён. Миграция не переносит и не изменяет фреймворк.

## ID и прежние пути

Историческая операция первоначального M2: копировался только реестр.
Следующая команда документирует прежний перенос; в текущем окружении M4 её не повторять:

```powershell
& 'E:/ComfyUI_windows_portable/python_embeded/python.exe' -s -B ./app.py `
  --adopt-registry 'E:/source/my/TOSAB/Book/TrueMoonTales/AMV/UI/.local/Registry.json' --check
```

До записи проверяются ID и корни всех проектов. Повторный вызов идемпотентен;
непустой отличающийся реестр не перезаписывается. Сами `Studio.project.json`, их
revision, asset_id, блоки, дубли, сценарий, таймлайн, ссылки Motion Context и
immutable History/Job/Request/Result не переписываются. Автоимпорт и reconciliation
при обычном старте отключены; `--sync-imports` — отдельная явная операция записи.

Старые относительные пути считаются от `legacy_root`. Новые внешние материалы
получают именованные пути. Повторная регистрация существующего физического файла
сохраняет его ID и исходную строку path. Если несколько ID после разрешения путей
указывают на один файл, Studio возвращает конфликт 409, а не объединяет их молча.

Действующий после M4 пример сопоставления старого имени:

```json
{"from":"TrueMoonTales/AMV/Clair","to":"@videos/Clair"}
```

Карта совместимости работает на границах Store: проекты, материалы, карточки,
контекст, история и URL. Подписанные снимки не редактируются поиском/заменой.
Ранее подготовленное, но ещё не запущенное GPU-задание после смены профиля или
физических путей следует подготовить заново: проверка снимка/хешей остаётся строгой.

## Профили и проверки

Omni.v1/v1.1 используют четыре включённых шаблона `Workflows/TemplateData` с
`Provenance.json`; чтение старого Research для подготовки больше не требуется.
Omni.v2 сохраняет собственные Templates и остаётся экспериментальным отдельным
CLI-профилем. Его контракт v2 не заменяет профиль Studio v1.1 одной сменой пути.
Параметры runtime передаются helper-процессам. Таймеры, watchdog, проверка владения
процессом, запрет повторной отправки и разделение prepare/launch/collect сохранены.
Обычный старт и `--check` не отправляют очередь GPU.

```powershell
& 'E:/ComfyUI_windows_portable/python_embeded/python.exe' -s -B -m unittest discover -s tests -p 'test_*.py'
node --test tests/test_*.mjs
```

Исторические отчёты Verification описывают прежнюю конфигурацию. Приёмка M2 и
точные контрольные SHA находятся в новом отчёте миграции. Исходная UI 0.14
сохранена в Book как архив для возврата; дальнейшие правки кода выполняются здесь.

## История M3 · состояние до переноса видео

После M3 активны внешние Texts/Lore/Arts. Их прежние пути разрешаются через
path_aliases: Arts и Handbooks — по префиксу, тексты/обложки/мастера — по точным
файлам из manifest. Это не переписывает авторские Studio.project.json или
immutable снимки. После изменения конфигурации перезапустить Studio. На этапе M3 видео
ещё оставалось в Book. После M4 действует запрет чтения Book из следующего раздела.

## M4 · Book отключён

Видео/Production/исследования находятся в TrueMoon.Tales.Videos. Конфигурация
`legacy_read_enabled: false` оставляет legacy_root только логическим пространством
старых имён: стат/чтение/запись туда запрещены, unmapped пути возвращают 403.
Aliases перенаправляют относительные и абсолютные старые строки до файлового IO.
Экспорт получает только реальные новые пути. Исторический prepared с config в старом
пространстве имён возвращает 409 без запуска/мутации; подготовить свежий дубль.
Новые prepare/launch работают с новыми физическими путями. Исторические снимки
не переписываются. Для применения конфигурации перезапустить Studio.


## Arts · категории в корне

Библиотека TrueMoon.Tales.Arts использует Characters/, Props/ и другие категории
сразу в корне. Mount @arts указывает на корень репозитория; пример нового адреса:
@arts/Characters/Claire/ComfyUI_00915_.png. Конфигурация сохраняет aliases для
старого @arts/Arts/... и прежнего Book/Arts/... без переписывания ID/истории.
После обновления Studio.config.local.json перезапустить уже открытый сервер Studio.
